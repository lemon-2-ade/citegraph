# ADR-001: Neo4j as the knowledge-graph store

**Status:** Accepted

## Context

The core data is a heterogeneous, highly connected graph: papers cite papers, authors
write papers and collaborate, papers belong to topics and venues. The most valuable
queries are multi-hop — citation neighbourhoods, "papers two hops from X that share a
topic with Y", shortest paths between papers — and the platform needs graph algorithms
(PageRank, centrality, community detection). Later phases need vector similarity
combined with traversal in the same query.

## Alternatives considered

- **PostgreSQL only (adjacency tables + recursive CTEs).** Simple operationally, but
  variable-length traversals become recursive CTEs that are hard to read and optimise,
  and there is no built-in graph-algorithm library.
- **PostgreSQL + Apache AGE.** Adds openCypher to Postgres but has a smaller ecosystem
  and no equivalent of the Graph Data Science library.
- **RDF triple store (e.g. GraphDB, Blazegraph) with SPARQL.** Strong for ontologies
  and reasoning; weaker developer ergonomics for property-rich edges (weights,
  confidence, provenance) and fewer analytics algorithms.
- **In-memory graph library only (NetworkX / igraph).** Excellent for analytics, but not
  a database: no persistence, concurrency or indexed lookup.

## Decision

Use **Neo4j 5** as the system of record for the research knowledge graph, with the
**Graph Data Science (GDS)** plugin for algorithms and native **vector indexes** for
embedding search (Phase 7).

## Consequences

- Cypher gives readable multi-hop queries; relationship properties carry provenance
  (`source`, `confidence`, `created_at`).
- GDS provides PageRank, betweenness, Louvain/Leiden, node similarity and path finding.
  Because GDS is an optional plugin (and not available in every environment, e.g. CI),
  the analytics layer also has a NetworkX backend over a projected subgraph. Both
  backends implement the same interface and are tested against the same fixtures.
- Neo4j Community Edition has no role-based access control; Cypher generated by an
  LLM (Phase 10) must therefore be validated and executed in read-only transactions.
- An additional stateful service must be operated and backed up.
